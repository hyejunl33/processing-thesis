# 졸업논문 프로젝트 아이디어 v2

> 작성일: 2026-11-12
> v1(코드 추적, 교실 서버, 탠저블 코딩, 이미지 QA)은 "교육 현장과의 연결"과 "AI가 코어인가"라는 기준에서 다시 검토했다.
> v2의 필터: **(1) 교육/교육현장의 실제 문제, (2) AI 모델이 코어(로컬 추론 또는 API), (3) Processing이 장식이 아닌 구현체.**

## 0. v2에서 중요하게 보는 것

- **AI가 답을 대신하는 프로젝트는 피한다.** AI는 표현을 바꾸거나, 관찰을 돕거나, 근거를 찾는 역할을 한다. 학생의 사고를 대체하지 않는다.
- **로컬 추론을 1급 시민으로 둔다.** Ollama/llama.cpp/whisper.cpp/ONNX Runtime으로 돌아가는 경로를 만들고, API는 품질/속도 비교와 폴백으로 쓴다. 이 자체가 논문의 기여가 될 수 있다.
- **Processing이 UI·실행·시각화·서버를 담당한다.** "Processing은 그림만 그리고 로직은 파이썬"은 피한다.
- **평가 대상이 분명하다.** 학생(개념 이해, 수행) 또는 교사(피드백 질, 수업 설계, noticing) 중 하나를 주인공으로 세운다.

## 1. MathLens — 문장제를 '조작 가능한 막대 모델'로 번역하는 AI

**한 줄 정의:** 초등 수학 문장제를 로컬 LLM이 구조화하고, Processing이 학생이 직접 만질 수 있는 막대 모델로 렌더링하는 학습 환경.

### 교육 현장의 문제

초등학생이 문장제에서 막히는 지점은 계산이 아니라 **번역**이다. "사과가 3개 더 많다"를 `+3`으로, "전체의 2/5"를 `전체 × 2/5`로 바꾸는 과정에서 막힌다. 교사는 학생마다 다른 문장제를 막대 모델로 그려줄 시간이 없고, 학생은 그림을 그려도 그것이 식과 어떻게 연결되는지 모른다.

### AI가 하는 일

- 학생이 입력한 문장제(또는 촬영한 문제지)를 LLM이 **문제 스키마**로 구조화한다.
  - 예: `{quantities, relationships: [part_whole, comparison], unknown, units}`
- LLM은 정답을 계산하지 않는다. **관계 구조만** 추출한다.
- 스키마는 고정 JSON 스키마로 검증하고, 실패하면 repair loop를 돌린다.
- 학생이 막대를 조작하다 막히면, LLM이 **정답이 아닌 발문**을 생성한다. ("전체 막대와 부분 막대의 관계를 먼저 볼까?")
- 선택: 문제지 사진을 OCR/VLM으로 읽는 경로. (뤼튼에서 한 이미지/텍스트 파이프라인 경험 활용)

### Processing의 역할

- 막대 모델 레이아웃 엔진(결정적 알고리즘, LLM 아님)과 드래그 인터랙션.
- 학생이 숫자/라벨을 막대 위로 옮기고, 관계를 연결하고, 식을 구성하는 캔버스.
- 힌트 패널, 단계별 로그, 교사용 대시보드.
- 로컬 LLM/API 호출, JSON 검증, 캐시, 오프라인 폴백을 Processing 앱 안에서 처리.
- 배포: Processing export 데스크톱 앱 + GitHub Releases. 로컬 모델은 Ollama 설치 스크립트로 안내.

### 로컬/API 추론 경로

- 로컬: Ollama `qwen2.5:7b` 또는 `gemma3:4b` (한국어 구조화 추출), llama.cpp 서버.
- API: OpenAI/Gemini (품질 비교군, 또는 로컬 실패 시 폴백).
- 비전(선택): Qwen2.5-VL via Ollama, 또는 OCR(Tesseract) + 텍스트 LLM.
- Processing에서는 `java.net.http.HttpClient`로 Ollama의 `/api/chat` 호출, `processing.data.JSONObject`로 스키마 검증.

### 연구 질문

- RQ1. AI가 생성한 **조작 가능한 막대 모델**은 정적 그림/텍스트만 제공할 때보다 문장제 해결과 전이에 효과적인가?
- RQ2. 학생의 **조작 로그**(막대 배치, 수정, 머뭇거림)는 오개념을 어떻게 드러내는가?
- RQ3. 로컬 소형 모델과 API 모델의 **스키마 정확도·지연·비용**은 교육적 사용에 충분한가?

### 평가 설계

- 대상: 초등 4~5학년 2개 학급(또는 예비교사 파일럿 후 초등 적용).
- 설계: 사전·사후 문장제 검사 + 통제/실험(텍스트/정적 그림 vs 조작 가능한 모델) + 전이 문항.
- 측정: 정답률, 식 세우기 정확도, 막대 모델 구성 정확도, 힌트 의존도, 인지부하, SUS.
- 분석: 대응표본/독립표본, 조작 로그 시퀀스 분석, 오류 유형 코딩.

### 경력 연결

- 뤼튼의 **LLM 전략 JSON(hook/appeal/cta)**, 고정 스키마, repair loop, 캐시 경험.
- 이미지/OCR/VLM 파이프라인 경험(문제지 사진 입력 확장).
- 부스트캠프의 실험 설계·지표·오류 분석.
- "AI가 정답을 주는" 것이 아니라 "AI가 표현을 바꾼다"는 교육적 포지셔닝.

### 리스크

- LLM이 관계 구조를 잘못 추출할 수 있다. → 스키마 검증 + 결정적 레이아웃 + 교사/학생 수정 UI.
- 문장제 유형이 다양하다. → 1차는 part-whole/comparison/곱셈 비교로 범위 제한.
- 학생 입력이 어렵다. → 문제 선택지 + 사진 입력 + 교사용 입력 모드.

### 한 학기 범위

- 4주: 문장제 유형/스키마/레이아웃 알고리즘 설계, 선행 연구.
- 6주: Processing 프로토타입(막대 모델, 드래그, 힌트, 로그).
- 4주: 로컬/API LLM 연결, 검증/repair, 캐시.
- 5주: 파일럿 + 본 적용, 분석.
- 5주: 논문 작성.

## 2. ReadEcho — 로컬 음성인식으로 읽기 유창성을 코칭하는 AI

**한 줄 정의:** 학생이 소리 내어 읽으면 로컬 Whisper가 듣고, Processing이 끊김·속도·정확도를 시각화하며, LLM이 다음 연습을 제안하는 읽기 유창성 코치.

### 교육 현장의 문제

읽기 유창성은 매일의 소리 내어 읽기와 즉각적인 피드백으로 발달한다. 하지만 교사 한 명이 25명의 읽기를 매일 들어줄 수 없다. 기존 앱은 녹음만 하거나, 정확도 점수만 주고, 왜 그런지 보여주지 않는다.

### AI가 하는 일

- 로컬 Whisper(whisper.cpp)로 학생의 읽기를 전사한다.
- 기대 텍스트와 정렬해 **대치·누락·삽입·자기수정**을 찾는다.
- 속도(WCPM), 멈춤 길이, 강세/억양(가능한 범위)을 특징으로 뽑는다.
- LLM이 "다음에는 이 문장을 끊어 읽어보자" 같은 **짧은 코칭**을 생성한다.
- 교사 대시보드에는 학생별 변화와 공통 오류가 보인다.

### Processing의 역할

- 마이크 입력, 파형/레벨 시각화, 단어 하이라이트, 멈춤 지도.
- 학생이 자신의 읽기를 다시 들으며 어디서 막혔는지 확인하는 인터페이스.
- 로컬 Whisper 프로세스/서버 호출, 정렬 로직, 세션 저장, 교사 대시보드.
- 배포: 데스크톱 앱(헤드셋 권장). whisper.cpp 바이너리와 모델을 함께 배포하거나 설치 스크립트 제공.

### 로컬/API 추론 경로

- 로컬: whisper.cpp (`ggml-small`/`ggml-base`, 한국어), 또는 faster-whisper를 subprocess로 호출.
- LLM: Ollama `qwen2.5:3b`/`gemma3:4b` (코칭 문장 생성), API 폴백.
- API 비교군: OpenAI Whisper/Azure Speech (정확도·지연 비교).
- Processing에서는 `launch()`/`exec()`로 whisper.cpp를 호출하거나, 로컬 HTTP 서버로 감싼다.

### 연구 질문

- RQ1. 시각적 유창성 피드백 + AI 코칭은 반복 읽기만 할 때보다 WCPM/ prosody를 향상시키는가?
- RQ2. 학생의 자기수정과 읽기 자신감은 어떻게 변하는가?
- RQ3. 초등학생 한국어 음성에서 로컬 Whisper의 정확도는 평가 도구로 충분한가?

### 평가 설계

- 대상: 초등 2~3학년 1~2개 학급.
- 설계: 4~6주 반복 읽기 intervention, 사전·사후 running record, 주간 WCPM.
- 측정: WCPM, 정확도, prosody rubric, 자기수정 횟수, 흥미/자신감, ASR 오류율.
- 분석: 혼합연구, 성장 곡선.

### 경력 연결

- NLP/음성 파이프라인, 로컬 추론, 정렬/평가 지표.
- "조용한 교실에서 매일 듣기"라는 교육 현장의 병목을 AI로 푸는 문제.
- 개인정보를 밖으로 보내지 않는 로컬 추론의 가치.

### 리스크

- 아동 음성 ASR 정확도가 낮을 수 있다. → 또박또박 읽기 과제, 짧은 문장, 신뢰도 낮은 구간은 교사 확인.
- 교실 소음/하드웨어. → 헤드셋, 조용한 공간, 오프라인 데모.
- 평가 타당도. → WCPM은 표준 절차, prosody는 루브릭.

### 한 학기 범위

- 4주: 읽기 유창성 문헌, 평가 도구, 음성 파이프라인 설계.
- 6주: Processing 오디오/시각화 + Whisper 연결.
- 4주: 정렬/오류 검출 + LLM 코칭.
- 5주: 파일럿 + 본 적용.
- 5주: 논문 작성.

## 3. EvidenceLens — 학생 작품의 '근거'를 비추는 AI 피드백 콘솔

**한 줄 정의:** 교사가 학생 작품 사진을 올리면, 로컬/API VLM이 루브릭 근거를 찾아 표시하고, 교사가 최종 피드백을 쓰도록 돕는 과정중심 평가 콘솔.

### 교육 현장의 문제

2022 개정교육과정은 과정중심 평가를 강조하지만, 교사는 학생별 작품(그림, 과학 일지, 수학 풀이, 독후감)을 읽고 개별 피드백을 쓰는 데 시간이 부족하다. 자동 채점은 교사의 판단을 대체하고, 학생의 과정을 놓친다. 필요한 것은 **AI가 근거를 찾아주고, 교사가 판단하는** 구조다.

### AI가 하는 일

- VLM이 작품에서 루브릭 항목과 관련된 **근거 영역**을 찾는다. (예: "뿌리, 줄기, 잎이 모두 표현됨", "관찰 기록에 변화가 시간 순서로 적힘")
- OCR로 글자를 읽고, 루브릭 스키마에 맞춰 구조화한다.
- LLM이 교사용 **피드백 초안**을 만들되, 근거와 함께 제시한다.
- 교사가 초안을 수정/승인하면 로그가 남고, 학생에게는 교사의 목소리로 전달된다.
- 교사 대시보드에서 반 전체의 루브릭 충족도/오개념이 보인다.

### Processing의 역할

- 작품 뷰어, 근거 bounding box/하이라이트 오버레이, 루브릭 패널, 피드백 에디터.
- 카메라/파일 입력, 이미지 전처리(회전/크롭/대비), 세션 저장(SQLite/JSON).
- VLM/LLM 호출, 스키마 검증, 캐시, 교사 승인 로그.
- 배포: 교사 노트북용 데스크톱 앱. 로컬 VLM이 어려우면 API 모드로 동작.

### 로컬/API 추론 경로

- 로컬 VLM: Ollama `qwen2.5vl:3b`/`7b`, llama.cpp + mmproj, 또는 Moondream.
- API: GPT-4o/Gemini 2.5/Qwen-VL API (품질 비교군).
- OCR: Tesseract (한국어) 또는 VLM에 위임.
- Processing에서는 이미지 base64 인코딩 후 Ollama `/api/chat` 또는 API 호출.

### 연구 질문

- RQ1. 근거 하이라이트 + AI 초안은 교사의 피드백 **질·속도·일관성**을 높이는가?
- RQ2. AI가 찾은 근거를 보는 것이 교사의 **판단 주도권/신뢰**에 어떤 영향을 주는가?
- RQ3. 교사 피드백을 받은 학생의 수정 질은 어떻게 변하는가?

### 평가 설계

- 대상: 예비교사 30명(접근 쉬움) + 가능하면 현직 교사 3~5명.
- 설계: within-subject counterbalanced (AI 없이 vs AI 근거/초안), 작품 세트 동일.
- 측정: 루브릭 점수, 피드백의 구체성/근거성, 소요 시간, 신뢰/주도권 설문, 인터뷰.
- 분석: 대응표본, 질적 코딩.

### 경력 연결

- 뤼튼의 **안전성/QA 파이프라인**, 이미지 검색, human-in-the-loop 검수.
- 멀티모달 파이프라인, 고정 스키마, 실패 시 폴백.
- "AI가 채점하는" 것이 아니라 "AI가 근거를 비추고 교사가 판단하는" 교육적 포지셔닝.

### 리스크

- VLM hallucination. → 근거 영역과 confidence를 함께 표시, 교사 승인 필수, 근거 없는 주장은 UI에서 제거.
- 개인정보/작품 저작권. → 익명화, 로컬 모드, 동의 절차.
- "자동 채점 도구"로 오해. → 연구 질문과 UI 카피에서 교사 판단을 전면에.

### 한 학기 범위

- 3주: 과정중심 평가/피드백 문헌, 루브릭/스키마 설계.
- 6주: Processing 뷰어/오버레이/에디터 + VLM 연결.
- 4주: 예비교사 파일럿, 근거 유용성 분석.
- 5주: 현직 교사 적용(가능 시), 분석.
- 6주: 논문 작성.

## 4. LessonLens — 교육과정에 근거해 수업을 설계하는 로컬 RAG

**한 줄 정의:** 2022 개정교육과정·교사용 지도서·교과서를 로컬에서 검색하고, 출처가 붙은 수업 계획을 생성하며, 교육과정 그래프로 맥락을 보여주는 교사용 AI.

### 교육 현장의 문제

교사는 수업 하나를 준비할 때 교육과정 성취기준, 교사용 지도서, 교과서, 평가 기준을 오가며 찾는다. 일반 LLM은 그럴듯하지만 출처가 없고, 교육과정과 어긋난 계획을 만든다. 교사에게 필요한 것은 **근거를 추적할 수 있는** 계획 지원이다.

### AI가 하는 일

- 교육과정 PDF/문서를 파싱해 청킹·임베딩하고, 로컬 벡터 검색(BM25+vector hybrid)으로 근거를 찾는다.
- LLM이 성취기준·차시·활동·평가를 포함한 수업 계획 초안을 만들고, 각 주장에 출처를 붙인다.
- 출처 검증: 인용문이 실제 문서에 있는지 확인하고, 없으면 표시하거나 재생성한다.
- 교사가 수정하면 그 수정이 다음 검색/생성에 반영된다.

### Processing의 역할

- 교육과정 그래프(단원-성취기준-차시) 시각화, 검색 결과/출처 뷰어, 수업 타임라인 에디터.
- 문서 인제스트 UI, 임베딩 캐시, 로컬 검색 인덱스, LLM 호출.
- 배포: 교사용 데스크톱 앱/로컬 서버. 문서는 기기 밖으로 나가지 않는다.

### 로컬/API 추론 경로

- 임베딩: Ollama `bge-m3`/`nomic-embed-text`, 또는 ONNX Runtime Java (e5-small).
- LLM: Ollama `qwen2.5:7b`/`gemma3:4b`, API 폴백.
- 검색: SQLite FTS5 + cosine similarity (또는 FAISS JNI).
- PDF 파싱: Apache PDFBox (Java).

### 연구 질문

- RQ1. 출처 기반 RAG는 일반 LLM보다 수업 계획의 **교육과정 정합성/근거성**을 높이는가?
- RQ2. 교육과정 그래프/출처 뷰어는 교사의 **탐색 시간과 신뢰**에 어떤 영향을 주는가?
- RQ3. 로컬 검색/생성의 지연과 비용은 실제 수업 준비에 acceptable한가?

### 평가 설계

- 대상: 예비교사 30명 + 현직 교사 3~5명.
- 설계: counterbalanced task (일반 LLM vs LessonLens), 동일 단원.
- 측정: 성취기준 정합성, 출처 정확도, 계획 완성 시간, 신뢰/사용성, 인터뷰.
- 분석: rubric scoring, 대응표본.

### 경력 연결

- 뤼튼/부스트캠프의 **RAG, hybrid search, FAISS, Airflow, LLM agent** 경험을 가장 직접적으로 사용.
- 교사 업무 자동화(AX) 경험과 교육과정 도메인.
- "출처 없는 LLM" 문제를 교육 현장에서 푸는 것.

### 리스크

- "또 하나의 챗봇"으로 보일 수 있다. → 교육과정 그래프와 출처 검증을 전면에.
- 문서 저작권/배포. → 사용자가 가진 문서를 로컬에서 인제스트, 앱에 포함하지 않음.
- 생성 품질. → 템플릿/스키마 + 출처 검증 + 교사 수정.

### 한 학기 범위

- 4주: 문서 수집/파싱, 청킹, 평가 지표 설계.
- 6주: Processing UI + 로컬 검색/LLM 연결.
- 4주: 출처 검증/그래프 시각화.
- 5주: 예비교사/현직 교사 평가.
- 5주: 논문 작성.

## 5. 와일드카드: FracLens — 조작물 위의 AI (수학 조작교구 + 비전)

**한 줄 정의:** 학생이 분수 타일을 책상 위에 놓으면, 웹캠과 로컬 VLM/비전이 배열을 읽고, Processing이 겹쳐 보여주며 적응적 발문을 던지는 조작교구 기반 분수 학습.

- **교육 현장:** 분수는 구체물 조작이 중요한데, 교사가 모든 조합을 관찰하고 개입하기 어렵다.
- **AI:** ArUco/색 마커로 상태를 결정적으로 인식 + VLM(선택)으로 자유 배열 해석 + LLM 발문.
- **Processing:** 카메라, 마커 검출, 분수 막대 오버레이, 발문 패널, 로그.
- **연구:** 조작교구 단독 vs AI 적응적 발문이 분수 개념/전이에 미치는 영향.
- **경력:** 비전 + 멀티모달 + 교육. 단, 하드웨어/교실 적용 리스크가 있다.

## 7. 추천

### 1순위: MathLens

- 교육적 문제(문장제 번역)가 선명하고, AI가 **정답을 대신하지 않으면서** 코어로 들어간다.
- Processing의 강점(조작 가능한 시각화)이 논문의 핵심 개입과 정확히 일치한다.
- 로컬 LLM/API, 스키마 검증, OCR/VLM 확장까지 경력의 폭을 자연스럽게 사용한다.
- 하드웨어 없이 학기 안에 완성할 수 있고, 초등 4~5학년 대상 평가가 현실적이다.

### 2순위: EvidenceLens

- 뤼튼의 QA/멀티모달/human-in-the-loop 경력과 가장 직접적으로 연결된다.
- 예비교사 대상 평가는 접근성이 좋고, "AI가 채점하지 않는다"는 교육적 포지셔닝이 강하다.
- 다만 "AI 채점 도구"로 오해되지 않도록 연구 질문과 UI를 조심해야 한다.

### 3순위: ReadEcho

- 읽기 유창성은 교육적 가치가 크고, 로컬 STT라는 엔지니어링 스토리가 좋다.
- 아동 음성 ASR 정확도와 하드웨어/교실 소음이 최대 리스크. 파일럿을 일찍 해봐야 한다.

### 4순위: LessonLens

- 가장 안전하게 끝낼 수 있고 RAG/agent 경력을 직접 살린다.
- 다만 "챗봇"과의 차별화(교육과정 그래프, 출처 검증)가 약하면 임팩트가 줄어든다.
